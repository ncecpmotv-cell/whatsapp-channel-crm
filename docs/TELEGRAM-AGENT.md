# وكيل تليجرام: تحليل، خطط محتوى، واعتماد بشري

تليجرام هو **واجهة الذكاء الاصطناعي** في هذا المشروع: تكتب له بلغتك، يقرأ بيانات قناتك من CRM عبر MCP، يقترح خطة، ثم **أنت** تعتمدها في التطبيق قبل النشر. الوكيل لا ينشر من تلقاء نفسه.

```
أنت (تليجرام) ──► PicoClaw ──MCP──► CRM (قراءة البيانات + إنشاء مسودات)
                                      │
                                      ▼
                         التطبيق /ui: أنت تراجع وتنشر
```

## ١) أنشئ البوت

1. افتح تليجرام → ابحث عن **@BotFather**.
2. `/newbot` → اسم → اسم مستخدم ينتهي بـ`bot`.
3. احفظ **التوكن** (سطر مثل `123456789:AA...`). لا تشاركه ولا تضعه في Git.

## ٢) اعرف رقمك في تليجرام

أرسل رسالة إلى **@userinfobot** أو **@RawDataBot**؛ ستحصل على معرّف رقمي مثل `976417275`. هذا الرقم يُستخدم لتقييد الوصول إلى بوتك.

## ٣) ضع التوكن والصلاحيات

التوكن يُخزَّن في ملف الأسرار الذي ينشئه PicoClaw (صلاحية 600):

```bash
PICOCLAW_HOME=~/.whatsapp-crm/picoclaw ~/.whatsapp-crm/bin/picoclaw onboard
```

`onboard` يسأل عن المزوّد (OpenAI/Ollama/…)، مفتاح الـAPI، وتوكن تليجرام — وهذا أبسط طريق. بديل يدوي:

```yaml
# ~/.whatsapp-crm/picoclaw/.security.yml
channel_list:
  telegram:
    settings:
      token: "123456789:AA..."     # توكن BotFather
model_list:
  default:
    api_keys: ["sk-..."]           # مفتاح المزوّد
```

ثم قيّد من يستطيع الكلام مع البوت في `config.json`:

```json
"channel_list": {
  "telegram": {
    "enabled": true,
    "allow_from": ["976417275"]
  }
}
```

`allow_from` قائمة معرّفات مسموحة. بدونها يستطيع أي شخص يجد البوت أن يقرأ بياناتك عبر الأدوات.

## ٤) شغّل الوكيل

```bash
~/.whatsapp-crm/bin/crmctl restart
~/.whatsapp-crm/bin/crmctl status        # pico : up
```

تحقق من الأدوات:

```bash
PICOCLAW_HOME=~/.whatsapp-crm/picoclaw ~/.whatsapp-crm/bin/picoclaw mcp test crm
```

يجب أن يسرد 14 أداة (`crm_search`, `channel_metrics`, `crm_create_channel_post`, …).

## ٥) جرّبه

أرسل إلى بوتك:

```
ما أدواتك المتاحة؟ وما آخر 5 منشورات على القناة ومشاهداتها؟
```

سيقرأ عبر `wa_channel_messages` و`channel_metrics`. إن ردّ بأنه لا يملك أدوات، فالتسجيل ناقص — أعد:

```bash
PICOCLAW_HOME=~/.whatsapp-crm/picoclaw ~/.whatsapp-crm/bin/picoclaw mcp add crm \
  "http://127.0.0.1:8085/mcp" -t http -H "Authorization: Bearer $BRIDGE_TOKEN" -f
```

## ٦) ماذا تستطيع أن تطلب منه

| الطلب | ما يفعله فعليًا |
|---|---|
| «حلّل أداء آخر 30 منشورًا: أي نوع محتوى يجلب مشاهدات أكثر؟» | `channel_metrics` + `wa_channel_messages` ثم جدول مقارنة |
| «اقترح خطة نشر لأسبوعين: 4 منشورات أسبوعيًا مع الأوقات» | يبني الخطة من بياناتك، ويمكنه إنشاء مسودات فعلية |
| «حوّل الخطة إلى مسودات في التطبيق» | `crm_create_channel_post` لكل منشور (تصل كمسودة) |
| «اقترح موعد نشر لكل مسودة» | `content_schedule` — يبقى الوضع مسودة حتى تعتمدها |
| «من العملاء الذين لم نتابعهم منذ أسبوع؟» | `followups_due` / `crm_search` |
| «اكتب لي 5 عناوين لمنشور عن …» | نص فقط، ثم مسودات إن طلبت |

## ٧) حدود الوكيل (مقصودة)

- **لا ينشر**: `AGENT_CAN_PUBLISH=0` افتراضيًا. حتى مع `1` يبقى القرار لك في الواجهة.
- **لا يعدّل منشورًا منشورًا**: المنشور على القناة غير قابل للتعديل من النظام.
- **الاستبيانات مرفوضة** في قنوات واتساب (خطأ 479) — سيخبرك بذلك بدل أن يعيد المحاولة.
- **لا يرى إلا ما تسمح به الأدوات**؛ لا يملك وصولًا لنظام الملفات أو لقاعدة البيانات مباشرة.

## ٨) حلقة العمل الكاملة

```
1) تحليل        أنت + الوكيل: ماذا نُشر؟ ماذا نجح؟ ما الفجوات؟
2) خطة          الوكيل يقترح: موضوعات، أنواع، أوقات، أهداف
3) مسودات       الوكيل ينشئها عبر MCP (أو أنت من الواجهة)
4) مراجعة بشرية أنت تفتح /ui/content، تعدّل النص، تختار النوع والموعد
5) اعتماد       «جدولة» أو «نشر الآن» — قرارك أنت
6) نشر          العامل يرسل عند الموعد ويحوّلها إلى «منشور»
7) قياس         المشاهدات/التمرير/التفاعل تعود إلى التقارير، والوكيل يحللها في الدورة القادمة
```

التفاصيل العملية في [`CONTENT-PLAYBOOK.md`](CONTENT-PLAYBOOK.md).

## ٩) أمان

- توكن البوت = تحكّم كامل بالبوت؛ من يملكه يستطيع قراءة رسائله. `chmod 600 .security.yml`.
- استخدم `allow_from` دائمًا؛ بوت مفتوح = تسريب بيانات العملاء.
- الوكيل يتصل بـCRM على `127.0.0.1` فقط، ويحمل `BRIDGE_TOKEN`؛ لا تضعه في محادثة أو لقطة شاشة.
- عند الاشتباه: `/revoke` في BotFather يعطي توكنًا جديدًا، ثم حدّث `.security.yml` وأعد التشغيل.
