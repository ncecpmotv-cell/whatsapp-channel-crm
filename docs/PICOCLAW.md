# PicoClaw configuration in this project

PicoClaw is a separate project; this repository does not patch it. What we do is **generate
and register** a small, documented surface. This page is the source of truth for *what we
change and why*, so an upgrade never silently loses the CRM wiring.

## Where things live

```
~/.whatsapp-crm/picoclaw/
├── config.json        # generated by `picoclaw config reset`; we add one MCP server
├── .security.yml      # tokens only (mode 600): telegram bot token, model API keys
└── workspace/         # agent files
```

`PICOCLAW_HOME` must point at that directory for every `picoclaw` command
(`install.sh` and `crmctl` set it for you).

## What the installer changes — and nothing else

| Step | Command | Effect |
|---|---|---|
| 1 | `picoclaw config reset` | writes a complete, schema-valid `config.json` (we never hand-write it) |
| 2 | `picoclaw mcp add crm <url> -t http -H "Authorization: Bearer …"` | adds `tools.mcp.servers.crm` |
| 3 | — | the bot token and model key stay yours, via `picoclaw onboard` |

A hand-written `mcp` key at the top level is **ignored** by PicoClaw; the CLI writes the
correct location. That was a real failure mode before we switched to `mcp add`.

## The keys that matter

```jsonc
{
  "agents": { "defaults": {
      "workspace": "…/picoclaw/workspace",
      "provider": "openai",              // any supported provider
      "model_name": "…",                 // your model
      "max_tool_iterations": 8           // keep it low on a phone
  }},
  "channel_list": { "telegram": {
      "enabled": true,
      "allow_from": ["<your-telegram-user-id>"],   // the only access control that matters
      "settings": {}                                // token lives in .security.yml
  }},
  "tools": { "mcp": { "servers": { "crm": {
      "enabled": true,
      "type": "http",
      "url": "http://127.0.0.1:8085/mcp",
      "headers": { "Authorization": "Bearer <BRIDGE_TOKEN>" }
  }}}},
  "gateway": { "host": "127.0.0.1", "port": 18790 }
}
```

The same shape, sanitized, ships as [`config/picoclaw.config.example.json`](../config/picoclaw.config.example.json).

## Verify

```bash
PICOCLAW_HOME=~/.whatsapp-crm/picoclaw ~/.whatsapp-crm/bin/picoclaw mcp list
PICOCLAW_HOME=~/.whatsapp-crm/picoclaw ~/.whatsapp-crm/bin/picoclaw mcp test crm   # exit 0 + tool list
```

`mcp test` exits `0` on a completed connect, `1` on failure and `3` when the server is not
in the config — usable from a script.

## Upgrading PicoClaw safely

`install.sh --upgrade` replaces the **binary** and the CRM checkout, and re-runs `mcp add`
(idempotent, overwrites the same entry). It never runs `config reset` again, so your model,
Telegram token and `allow_from` survive. To start over: `picoclaw config reset` then
`crmctl restart`.

## Limits

- No MCP tool filtering is configured: the agent sees all 16 CRM tools. If you want to hide
  write tools, add `"tools": { "include": [...] }` to that server entry.
- `allow_from` is the only access control — an empty list or a wrong id means "someone else
  can read your CRM".
- PicoClaw has no hot reload for MCP servers: restart the gateway after changes.
